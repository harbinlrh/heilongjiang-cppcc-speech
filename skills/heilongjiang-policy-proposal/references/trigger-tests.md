# 选用与执行场景

用例是审查规范，不代表已经完成真实研究、Word生成或邮件测试；外部动作不得为测试而真实执行。

| 请求或输入 | 应有行为 |
|---|---|
| 写一份黑龙江省跨市地养老转介的咨政报告 | 选用本技能，核验省级介入理由和地方差异，正式成稿默认Word。 |
| 将哈尔滨旅游投诉建议转为黑龙江省级建议 | 选用本技能，重查跨市地问题及省级职责，不能全篇替换地名。 |
| 只改哈尔滨市属公园扩音管理建议 | 不因哈尔滨属于黑龙江而选用省级流程；使用哈尔滨市级技能。 |
| 作者来自哈尔滨，请写全国养老制度建议 | 不因作者所在地选用本技能。 |
| 只审查黑龙江省提案，不改正文 | 返回问题和修订建议，不另写全文或Word。 |
| 创建省级写作技能，加入Word要求 | 创建技能指令，不把未来Word要求当成这次生成报告任务。 |
| 只给出哈尔滨单个项目，要求全省结论 | 保留样本边界，查补省级依据或收窄结论，不编造普遍性。 |
| 2026年公报只含2025年数据且用户限定统计期2026以后 | 不把旧统计期写成2026，说明缺口并查替代。 |
| 主张由省级直接修改国家专属制度 | 核验权限，转为依法协调或上级建言，不冒称现行授权。 |
| Notion去重清单不可用但可读已有稿 | 报告实际去重范围，继续独立工作，不声称全面无重复。 |
| 为本人新写省级稿，没有重复提供署名 | 使用个人配置双行署名，不改成省政协委员或省级组织。 |
| 要求主题和预览确认后才能写Word | 只交付待确认阶段，不先生成正式稿。 |
| 写完Word但没要求发邮件 | 不发送；已获准发送后还须遵守邮件确认及已发送核验规则。 |

检查入口能区分省级对象与市级/全国对象、每个参考链接有效、默认个人署名未被省级化；如调整规则，复查受影响用例并记录实际检查范围，不把静态检查称为完整端到端测试。
