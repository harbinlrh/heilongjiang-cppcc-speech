# 12号样稿的组织、文风、数据与版式

依据用户2026年10月提供的《12-应建立高风险商业体育赛事应急响应时间强制考核制度》。原始 DOCX 见 [assets/model.docx](../assets/model.docx)，保留原文用于对照；其体育事实未因作为样稿而成为其他稿件的事实来源。

## 内容组织

样稿17个普通段落，11个非空段落；全文2344汉字、2611非空白字符，其中摘要376汉字，正文从第二次作者身份“反映，”起为1944汉字。汉字按 U+4E00—U+9FFF 统计，全文含题目和摘要，正文不含题目和摘要。未指定篇幅时可参考全文约2300汉字的密度，不机械凑字数、段数或页数。

1. **题目**：陈述式制度动作句，直接指出应改变的环节。聚焦一个政策对象与主线，不强套“应建立”或“强制考核”；“关于……的建议”不是本样稿默认标题句式。
2. **摘要**：标题后保留一个空段，以“【摘要】”开头，同段嵌入已确认作者身份及“反映，”。接着解释核心概念，用具体情景说明区别或关键环节，提炼主要问题、形成机制和对策主线。情景只是帮助理解时应明示，不写成真实发生的案例。
3. **正文开头**：摘要后保留一个空段，以同一身份及“反映，”起句。再次通俗解释主题，交代容易混淆的边界或现行制度适用范围，使正文可以独立阅读；无需逐字照抄摘要。
4. **制度基础与问题引入**：一个连续段落说明现行安排及下一步需要补足的环节，末尾以“目前……存在的主要问题分析：”或自然等义表述引出问题。可加入直接相关的现状数据，不另设“现状”大标题。
5. **三项问题**：分别以“一是……”“二是……”“三是……”领起，各为一个连续段落。领起句先点明具体障碍，随后用真实数据或案例展开，解释发生机制，并说明现有规则已经覆盖什么、仍在哪个执行环节需要补足。三项按共同机制组织，不为凑数拆分一个问题。
6. **过渡**：“为此建议：”单独一段。
7. **三条建议**：分别以“一、”“二、”“三、”开头，动作性首句后同段展开责任部门、关键执行程序和必要边界。每条回应一个主要机制，可涵盖相关问题；监督、成本、例外和救济按实际需要融入，不追加第四条，不压成空泛口号。

不加独立居中署名、不加“现状—问题—建议”三个一级标题、不加口号式结尾；末尾四个空段仅为原样稿尾部留白，可在输出时去掉。保留用户指定文体和完整论证，结构忠于此样稿不意味着必须套用体育赛事的治理工具。

## 文风与数据用法

- 面向无专业背景的读者，先说“是什么、用来做什么、讨论哪个环节”，再讲制度问题。必要术语准确一致，数字后解释其意义，不用新术语堆叠来释义。
- 每个问题保持“判断—事实或实例—机制—规则衔接”的论述关系。案例先写清实际发生了什么、证据直接支持哪个障碍，问题领起句的强度不得超过证据。成功案例可说明实测表现、有效做法或评价口径，不能反推未披露的失败，也不能加上“若、可能”便充当已经发生的问题实例。
- 地域按用户指定范围筛选，要求国内案例时，国外材料不能替代所需的国内核心证据。用户明确要求负面实例时，优先核验对应对象实际发生的失败、故障、效率或可靠性不足，保留事实的时间、范围及披露性质。未指定负面取向时，不将这一偏好扩展为所有主题都必须找事故或失败；始终以案例能否直接支持判断为准。
- 核对案例对象、使用场景和评价指标是否与问题一致。演示、实验室测试、试点与连续生产分别陈述，跨场景材料只支持已观测事实；例如演示失误不直接证明工业工位运行失败，技术故障也不自动证明验收制度失效，后者须有对应流程或责任缺口的依据。
- 找不到足以支持某项问题的指定范围案例时，继续核查、收窄判断或调整问题组织，并在交付说明交代关键证据缺口；不能为凑三项问题拼接传闻、断章取义地截取数字，或把风险推演包装成实际失败。事实、技术不足与制度原因之间的推断须单独说明，不把先后发生当作因果。
- 样稿通过时间节点、人员数量、距离和操作步骤使问题可感知。新主题选择真正能说明问题的同类细节，不照搬体育数字，也不要求每段塞满数据。历史案例写清发生年份和当前借鉴范围；个案不证明全国发生率。
- 数据保留统计对象、时段、地区、单位和分母。企业自述、机构测算和采访回忆不写成官方统计；试点表现不写成规模化普及；从事实推导的风险使用相应条件和语气。关键事实不足以支撑判断时，调整论断而非只隐藏出处。
- 短判断后接完整解释，长短句交替。现状和问题占正文主要篇幅，对策相对精炼；不以密集小标题、名词清单和重复背景代替论证。保留现行制度的有效部分，明确区分已有义务与拟新增要求。

## Word 版式

以资产中的段落与节属性为依据，复制整份 DOCX 后，在 `word/document.xml` 的对应段落中替换文本，保留样式结构、字号、纸张设置和段落格式，不能把旧稿残留文字带入新稿。样稿原有 `word/fonts/font1.odttf` 至 `font4.odttf`、`word/fontTable.xml`、`word/_rels/fontTable.xml.rels` 及其内容类型和关系应完整带入，但内嵌字体可能只包含原稿用字，不能机械要求输出稿的字体字节永远不变。除下述有记录的字符覆盖修复和元数据处理外，其他 ZIP 部件的未压缩字节与原样稿一致；不要从空白文档仿建而无意丢失可用字体资源。

| 部位 | 实测版式 |
| --- | --- |
| 页面 | 单节 Letter 纵向，12240×15840 DXA；上下边距1361，左右1474；页眉页脚距离720；一栏；网格 linePitch360 |
| 标题 | 方正小标宋简体22磅，居中，不另加粗 |
| 摘要及正文 | 仿宋_GB2312 16磅，两端对齐，首行600 DXA即30磅，固定30磅行距，段前段后0 |
| 问题领起句 | 含“一是/二是/三是”的判断句为楷体16磅；随后同段恢复仿宋_GB2312 16磅，不另加粗 |
| 建议领起句 | 含“一、/二、/三、”及动作性首句为黑体16磅；随后同段恢复仿宋_GB2312 16磅，不另加粗 |
| 段落安排 | 标题与摘要之间、摘要与正文之间各一个空段；无表格、额外大标题、独立署名或页眉页脚内容 |

固定30磅行距来自段落属性，不能误用网格 linePitch360 代替。样稿内嵌上述四种字体，系统未安装不代表文档不能使用它们；原稿能正常显示也不证明子集覆盖新稿文字。生成前按标题、问题领起句、建议领起句和正文各自实际用字检查字符映射及可见字形，不能只查字体名称或映射存在而忽略空字形；正常空白字符不算缺字。生成后复核实际渲染字体及逐页字形。页数随正文自然变化，不固定为样稿的五页。

确认缺字后，优先使用本机同款、完整且可合法复用的字体补齐对应输出资源；需要嵌入时确认可嵌入，许可允许时可按新稿各文字段的实际用字重新生成子集，并同步有效的字体表、关系及内容类型。缺少可用同款字体时，选择覆盖完整的适当替代字体，记录原字体、实际采用字体、适用段落及必要部件变化，并在交付时披露，不把某次采用的替代字体设为所有新稿默认。字体修复只作用于输出稿，不改原始样稿资产；保留相应字号、领起句区别和段落版式。修复或替代后重新渲染最终全部页面，核对缺字、行宽变化和分页；程序字符覆盖检查不代替逐页视觉核验，未修复缺字不能称视觉通过。

### 模板包与元数据

原始样稿资产始终不改。生成的新稿允许以下有限例外，内部记录 `部件路径 | 操作 | 原值或原哈希 | 新值或新哈希 | 原因`，其余部件保持原字节：

- **字体覆盖修复**：按上述字符覆盖检查，补齐或替换对应输出字体资源，并同步必要的 `word/fontTable.xml`、字体关系、字体键及 `[Content_Types].xml` 条目；如需改变文本或样式中的字体指派，仅调整受影响部分。记录字符缺口、所用字体来源和实际名称、覆盖核验、部件变化及修复后逐页检查结果，不为保留原字节而接受缺字，也不连带改动无关格式。
- **核心属性**：更新 `docProps/core.xml` 的旧标题、修改时间等来源特定字段，使标题与新稿一致、时间反映实际编辑；原稿中的体育题目不得留在新稿元数据。作者信息按已确认身份处理，不把模板中的编辑账号写成新稿实际编辑者，也不编造审定、机构授权或时间。
- **旧缩略图**：清除 `docProps/thumbnail.wmf` 等原稿缩略图，同步移除对应包关系和 `[Content_Types].xml` 声明；修改这些公共部件时只处理缩略图相关条目，保留正文、字体等无关关系与类型，不留下悬空引用。
- **扩展统计**：如更新 `docProps/app.xml` 的字数、字符数、页数等字段，记录计数口径和最终渲染依据。不得沿用旧稿统计声称新稿结果，也不得凭估计伪造页数；未更新的模板缓存统计不作为验收证据。

交付前对照原样稿列出全部新增、删除和修改部件，核对每项均属正文替换或上述例外；检查核心标题及旧缩略图已清理、XML与包关系有效、实际字体覆盖完整，样式结构、纸张和段落格式没有无关变化。
