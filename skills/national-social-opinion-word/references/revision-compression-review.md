# 原意保留、机制重组与五项自评

适用于精简、限项、版本比较和评分修订，不取代新稿的个人样稿默认规范。用户当次要求优先。此方法来自2026年9月大型活动安全辅助岗位稿的三版本比较；需要例子时读 [版本比较案例](revision-case-safety-auxiliary.md)。

## 1. 先确定改哪篇、和哪篇比

- 读取实际文档，不根据文件名、版本号或此前助手声称的字数判断内容。记录文件路径、正文题目、署名、版本角色；同名v3可能内容不同。
- 有早期稿、用户修改稿和完成稿时，分开比较两个阶段。用户已完成的收题、删例、改结构不得归为本轮成果。最新确认稿为编辑基准，早期稿作回溯基准。
- 比较说明区分：用户已改、此次删减、此次合并、此次补足、仍待核。只替换词语不能声称增加制度论证。
- 保留原件，独立输出。仅比较或更新技能不自动改Word、发邮件或同步GitHub。

## 2. 建立不能丢的内容清单

锁定政策对象、核心制度工具、责任主体、关键证据、适用范围、执行动作、保障和救济。篇名可收窄，但不能借精简改变立场或取消原有重要制度安排。标题调整需要说明，用户已定题名优先。

逐项标记原段落的去向：保留、合并到何处、删除及理由、实质补充。合并前先提炼独立主张，合并后逐条找回；必要例外、权限限制、劳动保护、个人信息边界、申诉程序并非废话。明确区分主张保留与法律表述纠偏，不能以意思不变为由保留明显错误，也不能隐瞒实质改动。

## 3. 先重组，再压缩句子

用户仅说精简但未定幅度时，可按本范式以20%—30%为目标并说明；明确篇幅要求优先。精简模式未另定项数时，问题不超过5项、建议不超过6项；新写仍按个人样稿默认四问题六建议，不能自动套用本例上限。

1. 先删同一事实的二次介绍、反复证明必要性的背景、口号和删去不影响理解的比喻。摘要独立概括，正文不再照抄摘要。
2. 按共同原因或制度环节合并，不按相邻位置拼接。例如技能报酬与短期用工共同解释训练投入不足；培训记录与设备变化共同解释现场能力无法证明。
3. 每项建议只保留一个主要动作，再安排必要执行、保障和纠错。把设备适配放回现场核验，把事故归责放回独立评价，把试点指标统一放回评估，不在末尾不断追加同级建议。
4. 检查实质项数。不能将8组互不相干的建议藏进6个超长段落，不得重复编号或混用层级制造达标假象。合并后若仍有两条不相干主线，重新划分。
5. 长短句交替，段首有判断，随后解释具体机制。删套话不删推理，避免把正文压成提纲；删去前半句后检查是否留下残句。
6. 加厚只增加缺失的责任、程序、成本、边界、例外和验证方式；增加一句制度内容，尽量同步删去重复铺垫。无需用更长篇幅证明更有能力。

## 4. 字数计算和事实边界

- 比例公式：`(基准字符数－完成字符数) / 基准字符数 × 100%`。默认统计主文标题、署名、摘要、各级题目和正文的非空白可见字符，包含标点、数字；两版使用同一提取范围和方法。另报汉字数时明确为U+4E00—U+9FFF，不混用两种口径。
- 主文含表格、文本框、脚注或修订标记时需识别其内容和接受修订状态，不以仅提取普通段落冒充全文。评价表、修改说明与正文分开统计；字数限制另有口径时遵从用户。
- 多个基准分别计算。完成版相对上传修改稿合格，不代表相对早期稿也合格。不要靠删署名、缩字号、压行距或减少页数完成文字压缩目标。
- 压缩不等于重新核验政策。新增或实质改变法律、统计、案例结论时查一手依据；编辑保留的未核事实不能称已验证。不能把个人修订稿当作官方证据。
- 数字分为事实和拟议参数。抽测比例、试点数量、期限等未有既定依据时明确写为建议，不在后续稿件中当现行要求。预警信号不直接等于违规，参考工资不等于法定标准，采购限制和数据互认均须有适用依据与程序。

## 5. 五项严格自评与修订

五项各按100分评价，等权平均为总分。评分是编辑自评，不代表外部专家、事实核验通过或报送采用。用户要求不到90分全改时，逐项达到90才满足该评分要求，不能只看平均数。

| 评分点 | 核查证据与扣分依据 |
| --- | --- |
| 原意与关键措施保留 | 原主张均有去向；主题、主体、权利、例外和核心工具不被删失；实质变动明示 |
| 精简与信息密度 | 同口径比例达标；重复、无效铺垫被删除；重要论证和证据未被挤掉 |
| 结构与因果关系 | 项数及编号正确；按共同机制合并；问题与建议可对应；不存在多主题塞段 |
| 制度可执行性与证据边界 | 谁做、怎么做、成本、权限、保障可识别；事实与拟议参数分开；重要待核未掩盖 |
| 语言与阅读节奏 | 无残句、歧义、套话及重复句式；正式而自然；长段有中心且可读 |

初审先记录具体缺陷、原文定位和分数，再改稿；复审记录改动位置、剩余扣分理由及复评分。不得事后补造初评分或简单把89改成90。没有先行评分记录的旧稿只能标为本次回溯评价，不能宣称历史实测。

硬性不合格优先于分数：关键事实失实或未核而左右结论、核心主张丢失、压缩幅度或项数不达标、Word缺字截断，均不得用高平均分掩盖。能修则继续；必须用户补证或决定时说明缺口，不通过空泛措辞把不确定性伪装成解决。若目标压缩会损害原意，明确冲突和实际幅度。

## 6. 成品交付

正文、修改说明、自评表分离，除非用户要求不把自评塞入提交稿。给出基准与完成数、缩短比例、问题/建议项数、主要变化、评分及剩余限制。Word按现有文档流程检查最终全部页面；字体替代、行距调整需披露，不能称完全保留原版式。需要提交稿时交付可编辑独立Word，当前仅更新技能时不额外生成文稿。
