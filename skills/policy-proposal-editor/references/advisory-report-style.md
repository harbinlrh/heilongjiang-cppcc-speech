# 咨政报告固定结构

用于用户明确要求“咨政报告”或“资政报告”。当次指定结构、篇幅、报送层级或新样稿优先；本文件只补足未指定部分，不移植其他样稿的事实、署名、数字、调研经历或机构名称。

## 成稿结构

完整报告依次为：题目、已确认署名、摘要、现状、主要问题、对策建议。不得另设“事实核验与适用边界”“参考依据”“资料来源”或参考文献章节。

- **摘要**：用一至数段概括政策对象、核心矛盾、基本判断和报告主张，不重复后文，也不放来源说明。
- **现状**：交代已核实的政策背景、运行情况、数据或案例。事实必须有内部证据记录支持，正文不展示出处、链接、引用编号或研究过程。
- **主要问题**：围绕机制、流程、责任、资源或监督等障碍展开。问题数量以实际内容确定；不得由单一个案、服务名单或相关性扩大为普遍失职或因果结论。
- **对策建议**：与问题逐项对应，按办理顺序组织。每项说明责任主体、办理动作、适用条件、资源或程序安排，以及评估、反馈或调整机制；上级权限事项写为报请、协调或授权申请。

## 内部证据与交付边界

每项进入正文的关键事实，在内部工作记录中至少保留：主张、来源机关、原文链接、发布日期、统计期或生效日、地域、支持边界和核验状态。证据记录用于事实复核和后续追溯，默认不随聊天成稿、Word或邮件附件交付，也不整理成参考文献。

法律、法规、政策文件的名称及必要适用条件，只有在它们构成权限依据、办理标准或正文事实时保留；不得添加发布机关、链接、引用格式或检索说明作为来源包装。无法核实的事实删除或收窄，不能为了充实“现状”或“问题”而补造数据、调研经历或地方数量。

## 交付前检查

核对章节顺序完整，摘要与现状不重复，问题和对策逐项对应；检查每项关键事实均有内部可追溯依据，且正式稿不含任何来源包装。按当次要求控制篇幅和段落密度，不因固定结构机械凑足问题或建议数量。
