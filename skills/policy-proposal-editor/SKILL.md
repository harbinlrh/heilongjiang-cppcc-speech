# 提案撰写与样稿改写

交付主题和立场明确、符合指定范式、依据可追溯且建议能办理的成品；改稿时保留原稿核心主张。本用户完整成稿默认继续生成独立Word，正文不含引用标记、检索说明或链接。邮件按当前任务的发送指令办理；技能中的收件人偏好不代替具体文件的发送授权。同步仓库另需明确要求。

## 选择写作模式

- 没有上传样稿，或指定沿用产业园区提案风格时，直接读取[内置产业园区提案范式](references/builtin-park-style.md)。该文件独立提供结构、论证、段落和语言规则，无需原始Word、历史对话或本机附件。不得仅因缺少样稿要求用户补传。
- 提供新样稿时，以当次明确要求、新样稿、内置范式的顺序确定写法；新样稿的结构覆盖内置默认，不混合相互冲突的框架。
- 要求改写且有原稿时做实质改写；只有明确主题和报送层级也可直接起草，先研究核实相关依据。缺少影响政策设计的主题或管辖范围才澄清；缺少本地证据应收窄事实表述，不编造数据补齐结构。
- 用户仅要求成稿语言清理时，采用局部最小修改，不重组结构或自动压缩篇幅；要求实质改写或按比例精简时，先按授权完成删并和重组，再做语言复核。仅排版、拆分、转格式不自动授权改文。

## 锁定输入与参照范围

- 先分清目标原稿、风格样稿、事实材料及用户已确认版本，记录真实文件名与哈希。不能按附件顺序、文件大小推定哪份是终稿。
- 完整读取正文、表格、超链接、脚注及署名；识别来源附录，不把删除附录算作正文压缩。原件保留，成果另存。
- 当次题目、篇幅、报送层级及新样稿优先。样稿提供组织方式、论证密度、语言强度；仅要求学习文风时，不自动复制其版式。样稿中的机构署名、调研经历、数字和政策不随风格移植。
- 保留目标稿作者及已授权身份。地域按政策对象判断，不能因作者所在地改变报送层级。哈尔滨、省级或全国专门规范仅在相应任务且当地可用技能存在时读取，不依赖固定机器路径。
- 研究生论文、政策文件及研究报告作为事实与分析材料使用，吸收内容后独立组织政策论证，不照搬摘要或逐段转述附件。正文直接论述具体问题、机制和建议，不介绍附件、研究过程或写作依据，不出现“政策文本研究提出”“论文指出”“根据所提供材料”等来源话术，也不换成“有关研究表明”。来源追溯留在内部记录；必要的法规名称、适用条件及事实限定保留。具体转写及验收按[附件内容融入正文](references/policy-language-review.md#附件内容融入正文)执行。

## 改写主流程

实质改稿读取[结构迁移与压缩](references/editorial-method.md)，先形成保留、合并、删减、补足的简短映射。直接起草则先确定核心问题、证据边界与办理环节，再落笔。

1. 提炼样稿怎样推进观点：开头如何界定问题，证据放哪里，小标题怎样落到动作，建议怎样解释责任和执行条件。样稿若为总述后直接列建议，可把原稿问题融入对应措施；不强加独立问题章节，内置范式默认四项建议，但当次要求和实际办理环节优先，不凑项或强拆措施。
2. 核验影响结论的事实。优先中央及属地一手来源，记录发布日、统计期、生效日、地域、链接及支持边界。按用户年份限制筛选，最新发布日期不能冒充最新统计期。临近交付有新发布时更新相关数据；无法核实的断言删除或收窄，不能补写本地数量或调研经历。
3. 合并重复背景和表达同一条件的赘述，不删除独有的限定、否定或例外；保留机制：谁处理什么、凭什么办理、如何纠错、资源从哪里来。数字差异、单一个案、服务名单或相关性不能直接升级为造假、普遍失职或因果结论。
4. 把政策建议写到相应权限内。新增数据使用、试点、财政支持或权利限制时，交代依据、必要范围、人员资金、异议和调整办法；上级事项写为报请、协调或授权申请。建议参数明示为拟议安排。
5. 编辑后反查每项重要风险是否仍有处理办法。既精炼文字，也消除重复论证；不为压页删掉资格边界、群众救济、费用来源或持续服务。
6. 新写或实质改稿完成事实、权限和论证核验后，交付正文或制作Word前，读取[成稿语言复核](references/policy-language-review.md)；仅做语言清理时直接按该参考执行。只改有明确表达问题的局部，保留必要前后对照，复核事实、条件及判断强度；发现证据问题返回第2步，不用润色掩盖。

## 文风与验收

标题只聚焦一个主题，明确一个核心问题或制度动作。禁止使用“某某与某某”式并列标题，也不能换用“和”“及”“、”堆叠多个主题。改写时提炼统领全文的单一主题，相关措施放入正文；交付前单独检查标题是否聚焦。

默认作为用户的文章润色编辑，去掉AI味，尽量口语化，保留用户的观点、事实和个人语气。每次润色及交付前语言复核，必须执行[成稿语言复核中的九条规则](references/policy-language-review.md#用户指定的九条润色规则)。这些规则是用户明确要求长期加入本技能的偏好，优先于内置样稿的通用文风；用户后续明确要求可覆盖。仅做润色时不新增原文没有的加粗、emoji或小标题，也不套用提案结构。四项建议可用自然段承载，不为套用样稿另加小标题或加粗。

用具体主语和动作，连贯自然段，句长服从意思，不为制造节奏强行拆并。立场明确但不夸大事实；删无信息的套话，不以编号、否定句、并列项、长句、标点或规范术语本身判为问题。个人样稿优先于通用文风偏好，但不能覆盖事实及权限约束。保留原文已有的语气、口头禅和不影响理解的不完美表达，不虚构经历或添加口头禅。除上述明确保存的九条规则外，其余禁词、标点和日期要求以用户当次指示为准。

按事实、结构文风、逻辑保全、可执行性、交付一致性五项检查。只有用户要求评分时才给分，各项低于其门槛的先修订；分数不能替代核验，也不虚称客观满分。用户只要完成版时，将检查留在工作记录。

## 报告完成后的交付闭环

- 完整报告、提案或社情民意写完后，不停留在聊天正文，继续读取[成品与交付](references/delivery.md)，依次执行：生成独立可编辑Word → 核对正文并逐页检查排版 → 按当前授权发邮件 → 独立核验已发送 → 交付文件入口和真实邮件状态。
- Word只保留题目、已确认署名和正文，不含引用标记、检索说明或链接。当前明确“只要文字”“暂不生成”时不生成；只讨论、审稿、局部润色或修改技能不触发成稿交付。
- 当前要求“发我邮箱”“生成并发送”或采用下列完整流程调用时，Word核验通过后直接调用可用邮件交付技能，收件人采用用户当前指定或已确认的本地配置，不重复索要同一发送确认；要求“确认后发送”时须等待确认。未要求发送或明确“暂不发送”时只交付Word，不从历史记录推定授权。
- 只有文件核验和已授权的邮件核验均通过，才能称完整交付。发送受阻或结果不明时仍交付已完成Word，说明未完成环节，不自动重发或绕过权限。
- 创建或改进技能时提炼通用规则；只有另有授权才同步GitHub。同步技能不附带上传原始稿、作者资料、邮箱信息或发送凭证。

完整流程调用：`$policy-proposal-editor 根据附件撰写提案报告，完成后生成Word，核验后发到用户指定邮箱。`
