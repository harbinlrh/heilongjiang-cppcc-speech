# 仅在失败或能力疑问时读取

|当前证据|分类及动作|
|---|---|
|截图或旧回复称“禁止发送”，无原始错误|仅为历史线索；只读检查当前工具是否存在及profile，不把推测当当前权限。不要发送探针邮件。|
|未发现附件发送工具|查当前工具目录和参数；无禁止证据且有允许的登录UI才可按入口流程选择UI，否则BLOCKED并说明缺连接器。|
|profile授权/登录失效|BLOCKED，请用户重连Gmail；不索取密码或令牌。|
|明确政策/权限拒绝|BLOCKED，保留原始原因，不循环重试，不换UI/SMTP/账号/脚本。用户需通过产品允许的方式恢复权限；一句“同意”不能覆盖更高层禁止。|
|明确审批请求大小限制且未发送|BLOCKED，说明这是请求预算而非Gmail容量；提出调整方案，得到新授权且当前政策允许后再预检执行。不能自动拆分规避审批。|
|超时、响应缺message ID、网络返回不明确|UNVERIFIED，仅做已发送搜索；不得自动重试。匹配记录存在但无发送ID可交叉确认时说明证据限制，不虚构成功。|
|某批SENT已核验，后批失败|逐批记录；停在失败批，不重发前批。恢复发送需用户明确指向尚未完成的批次。|
|返回成功但已发送暂未匹配|UNVERIFIED，可做有限只读复核，不能再次发送。|
|附件名、数量、字节或MIME不符|UNVERIFIED，说明差异；不删邮件、不自动补发。|

诊断输出必须包括：当前证据、已做/未做、是否可能已发出、下一步所需用户动作。只在实际创建了草稿时用DRAFT；没有草稿不能声称已备好草稿。SENT仅代表发件系统记录发送，不承诺QQ入箱或已读。用户反映未收到时，经授权检查退信等相关证据，不用重复发送来代替诊断。
